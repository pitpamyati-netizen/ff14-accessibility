# Выпуск русской версии на GitHub

Релизы публикуются в [нашем форке](https://github.com/pitpamyati-netizen/ff14-accessibility/releases).
Готовый ZIP прикрепляется к релизу; сборки и местные журналы не добавляются в Git.
Исходники доступны отдельно по метке `vВЕРСИЯ` и через GitHub Source code.

Публикация выполняется вручную по запросу владельца. Обычная отправка коммитов
не выпускает новый плагин автоматически. Для сборки нужны Windows, .NET SDK 10
и совместимый Dalamud API 15; для публикации — Git и авторизованный GitHub CLI `gh`.

## Подготовка

1. Увеличить `Version`, `AssemblyVersion`, `FileVersion` в проекте и `PluginVersion`
   в `Plugin.cs`. Они должны совпадать. Уже опубликованные версии не заменять.
2. Обновить `README-RU.txt`, `README.md`, `CHANGELOG.md`, `CURRENT_STATE.md`
   и `VERIFICATION.md`. Указывать фактические проверки; игровую проверку описывать отдельно.
3. Сохранить описание релиза в `docs/releases/ВЕРСИЯ.md`: изменения для игрока,
   установка, проверенные свойства и оставшиеся ограничения.
4. Выполнить из корня проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Build-Local.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-Local.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Package-Local.ps1
```

Сборка Release не устанавливает плагин в игру. Упаковка проверяет все файлы ZIP,
их контрольные суммы, версию DLL и отсутствие исходников и отладочных файлов.
Если ZIP этой версии уже существует, новый архив получает суффикс времени;
для публикации использовать путь нового архива из вывода команды.

5. Проверить состав изменений, сохранить их коммитом и отправить рабочую ветку в `origin`.
   Не отправлять логи, настройки, резервные копии или содержимое `artifacts` в Git.

## Публикация

Пример для первого выпуска; в следующих выпусках заменить версию и путь архива:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Publish-Release.ps1 `
  -ArchivePath artifacts/releases/FF14Accessibility-6.08.73-RU-no-source.zip `
  -NotesFile docs/releases/6.08.73.md -CheckOnly

powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Publish-Release.ps1 `
  -ArchivePath artifacts/releases/FF14Accessibility-6.08.73-RU-no-source.zip `
  -NotesFile docs/releases/6.08.73.md
```

`-CheckOnly` проверяет файлы и отправленный коммит без публикации.
Обычный запуск создаёт релиз с меткой `v6.08.73` на точном текущем коммите.
Скрипт отказывает при несохранённых изменениях, неотправленном коммите,
чужом адресе `origin`, устаревшей сборке, несовпадении ZIP или уже существующей метке.
Каждый файл архива повторно сравнивается с подготовленной сборкой и установщиком.
Запуск тестов выполняется отдельно на шаге подготовки; скрипт не проверяет игру.

К релизу прикрепляются архив с постоянным именем без суффикса времени и
`SHA256SUMS.txt` с контрольными суммами ZIP и основной DLL внутри `plugin`.
Исходники публикует GitHub отдельно. Старые релизы скрипт не редактирует.

После публикации проверить страницу релиза, скачать прикреплённый ZIP в отдельную
папку и сравнить его SHA-256 с подготовленным файлом. Записать результат в
`VERIFICATION.md`. Если публикация оборвалась, сначала посмотреть её состояние
на GitHub; не удалять существующий релиз и не передвигать метку для повторной попытки.

## Главная страница

В настройках форка главной выбрана `feature/russian-accessibility-recovery`,
чтобы GitHub показывал русскую версию и её инструкцию. `main` остаётся основой автора.
Описание и ссылка в блоке About ведут к русской сборке и последнему релизу.
Для сообщений игроков включён раздел Issues.
